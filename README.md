## Запуск тестов

1. Установите любое IDE для разработки: [Jetbrains GoLand](https://www.jetbrains.com/ru-ru/go/) (Платное или по студенческой лицензии), [VS Code](https://code.visualstudio.com/) (бесплатное).
2. Установите [Git](https://git-scm.com/install/) на компьютер
3. [Установите](https://go.dev/doc/install) Go версии 1.25.1
4. [Настройте](https://docs.github.com/ru/authentication/connecting-to-github-with-ssh) доступ к своему Github-аккаунту
   по SSH-ключу.
5. Склонируйте себе репозиторий: `git clone <путь к вашему репозиторию>`
6. Подтяните необходимые зависимости через команду в корне проекта:

```bash
   go mod tidy
```

7. В файле `.env.override` (создайте его в корне, если нет) выставьте правильные значения для переменных окружения:

```
TEST_LOGIN=your_login
TEST_PASSWORD=your_password
```

   Логин и пароль нужны от аккаунта на [TestBoard](https://testboard.avito.com/). Мои данные лежат в файле `.env.override`, к которому нет доступа, поскольку он добавлен в `.gitignore`. Если потребуется, готов дать логин и пароль своего аккаунта, с помощью которого запускал все тесты.

8. Для запуска всех тестов достаточно выполнить команду в корне проекта:

```bash
  go test -v -count=1 ./...
```

   Флаг `-count=1` отключает кэш результатов, чтобы тесты каждый раз реально ходили в API.

9. Отдельный пакет с тестами можно запустить командой:

```bash
  go test -v -count=1 ./tests/scenarios/favorites/
```

## Сценарии

| Пакет                                | Что проверяется                                                                                                                              |
|--------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|
| `tests/scenarios/myAdvertisement`     | Получение своих объявлений, 401 с неверным токеном                                                                                         |
| `tests/scenarios/advertisementSearch` | Поиск объявления по подстроке в названии (начало, середина, конец, разные регистры)                                                         |
| `tests/scenarios/createAdvertisement` | Создание объявления со всеми параметрами: объявление доступно по id, находится в поиске, фото загружены. Невалидные параметры, запросы без авторизации |
| `tests/scenarios/favorites`           | Добавление в избранное и удаление, пропадание удалённого объявления из избранного. Несуществующее объявление, 401, повторное добавление (409), своё объявление (403), невалидный id (400) |

Позитивные и негативные сценарии лежат в отдельных файлах (`*_test.go` и `*_negative_test.go`), общая подготовка
сьюта лежит в `suite_test.go`.

### Особенности

- Тесты сами создают нужные объявления и удаляют их после себя, поэтому их можно запускать много раз подряд.
  Для фото использую файлы из `testdata/`: в объявление загружаются 3 фото (максимум), а все 4 отправляются в
  негативном тесте на превышение лимита.
- Своё объявление нельзя добавить в избранное, а удалить объявление может только владелец. Поэтому сьют `favorites`
  в начале регистрирует второго пользователя со случайным email: он создаёт объявления, а пользователь из
  `.env.override` добавляет их в избранное. Второй аккаунт заводить вручную не нужно.
- Тестовый стенд иногда отвечает 503. Раннер повторяет такой запрос до 3 раз с паузой в секунду
  (`internal/helpers/api-runner/retry.go`), остальные статусы не повторяются.
- Фактические ограничения сервера отличаются от swagger: название до 50 символов (в swagger 255), описание до 500
  (в swagger 1000), ручка `GET /advertisements/{id}/photos` требует авторизацию. Тесты написаны под фактическое поведение.

## Логирование

Для включения логирования request/response в консоль нужно выставить переменную окружения `DEBUG=true` в
`.env.override`

## Запуск линтера

1. Установить приложение [golangci-lint](https://golangci-lint.run/docs/welcome/install/local/)
2. Запуск линтера (из корня репозитория):

```bash
  golangci-lint run
```
